# c11.102 核查记录

车主确认照片版本为此前提供的最新版 c11.101。原车音源正常，CarPlay／蓝牙音乐播放进度前进但无声；是否已在 Android 设置中强行停止 DiPlay 后复测蓝牙，仍待回复。

## 已确认的软件缺项

C11 的 ClusterMapPresentation 创建 TextureView 未改变 Android 默认 isOpaque=true；C11ClusterRoute.configureWindow 只有透明背景，无显式 TRANSLUCENT 格式。补齐二者，保留既有横向 DST_IN 渐变。模拟像素测试新增同一横坐标在顶部、中部、底部一致性，Presentation 测试检查 TextureView 和窗口实际配置。仍无实车 SurfaceFlinger／GPU 合成验证，不能声明上下融合已恢复。

## 仪表布局

c11.101 的 50/50 安全区中心请求与物理窗口中心一致，但车主实测官方 INSTRUMENTS 内容中的地图车标仍偏右。官方转向卡属于 iPhone 输出的视频内容，本地无法当作独立 View 改尺寸；整体缩小流会同时改文字、地图和车标，不能作为可靠居中修复。不得再把参数断言描述成像素位置验证。保留当前官方模式与红绿灯能力，不盲改坐标或裁切。

## 双屏模式

流 110 与 111 分别由 iPhone 输出，现有 changeMapZoomLevel(alt UUID) 只能请求仪表缩放步进；源码未提供经验证的全览／跟车状态回传与设置。没有新增虚构指令、反转按钮或强制镜像，也不声称已同步。

## 音频

C11MusicPolicy 只向白名单本机音乐会话发 pause/play；未发现全局静音操作，但不能据此排除间接焦点竞争。CarPlayMediaKeys 持有媒体会话与焦点，detach 同一 controller 时 releaseLocked 释放并 abandon；onSessionEnded 后会重连，因此仅“断开画面”不等于应用已经退出。AndroidMediaSink 在通话前保存音频 mode，关闭时恢复原值，若原值就是 MODE_IN_COMMUNICATION 会恢复为 3；旧报告存在该现象，但不能证明当前故障同因，也不能未经确认强制设置 MODE_NORMAL 干扰原车电话。

播放进度前进不能证明 CarPlay 已收到非零 PCM、AudioTrack 有输出或原车蓝牙选中了对应路由。c11.101 已记录 Audio: starting / decoder stats / routeType / playbackAdvanceFrames 与焦点日志；需要当前故障报告，不能沿用 c11.9 的通话录音全零作为音乐无声证据。c11.102 补充只读当前 mode、媒体／通话音量与静音、蓝牙状态和可用设备，后者不是活动路由证明。

未执行车机 ADB、Global 写入或系统修改。未处理此前暂缓的偶发音量变小。
