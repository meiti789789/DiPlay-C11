# C11 自动跟进上游发布

工作流：`.github/workflows/integrated.yml`。现有每 6 小时计划保留，也可在 Actions 中手动运行。上游为 `shihabal3amri/DiPlay`，本地 C11 补丁保存在 `integrated/`，不直接合并覆盖它们。

1. 分页读取所有发布，按数字版本选择带 APK、源码及 SHA256 的完整发布。支持原作者当前使用的 GitHub prerelease，不跟随每次开发分支提交。
2. 已完整发布的 C11 版本直接跳过；服务端暂时少返回上游版本时也不发布降级包。若同名发布不完整或为草稿，直接报错，禁止自动覆盖。
3. 将上游版本标签解析为确切 commit SHA，再检出该提交。重新应用 C11 源码补丁；上游锚点不匹配时立即失败。
4. 核对所有 32 个 C11 overlay 文件的完整内容、115 个原设置键和设置文件名；检查仪表 #2 路由、帧门控、独立尺寸、方控连接、官方 INSTRUMENTS 内容、190% 自定义卡、渐变和自己的 OTA 接口等关键连接仍在。文件数和键数可随今后有意修改适配增减；当前清单见 `protected_settings.json` 和 `verify_contract.py`。
5. 执行上游 AGENTS.md 要求的全部单元测试、三个应用 lint 与三个调试构建。失败不删除或跳过测试，附件保留供排查。
6. 用本项目固定签名正常源码编译 release APK。检查包名 com.c11.diplay、原签名 SHA256、minSdk 不高于 28、签名在 API 28 可验证、版本名符合预期、versionCode 比最近完整发布更大。旧 c11.104 的已验证 versionCode=40104 是首次迁移基准；以后从上一版的 `c11-build.json` 读取版本号证据，缺失则停止发布。
7. 全部通过后新增发布，附 APK、完整对应源码、指南、上游来源、`c11-build.json` 和校验文件。现有应用继续从本仓库检查更新，不跳转原作者包，不更换签名、不清除车主设置、不静默安装。

失败时 Actions 显示失败步骤与摘要，不创建新版本；当前可用发布保持原样。无法自动适配的上游接口变化需要以后修改补丁，不能保证任何未来版本都能无人工干预地合并，也不能用软件测试代替实车验证。现有音乐按键启动、音频或双屏视角问题不会因为同步成功就被宣称已修复。

本轮只修改 GitHub 同步和保护机制，不修改 c11.104 的应用运行代码、图标、名称、车标位置或设置，不需要为此重新安装 APK。未执行车机 ADB，也不写车机系统设置。

## 每次发布的 OTA 核验与失败通知

OTA 选择使用完整数字版本 `(上游主版本, 次版本, 补丁版本, C11 修订号)`，例如 c11.100 大于 c11.99、c11.10 大于 c11.9。GitHub 网页或原始 API 的历史列表顺序本身不可靠，客户端已有数字扫描；每次发布还会实查旧 c11.9 读取的首条是否为本次新版本。

发布先上传完整草稿，再公开，并用 c11.9 的无认证请求访问真实 API。检查最新版完整性、数字选版、首条兼容、公开 APK 地址、校验文件和实际下载 APK 的 SHA256。网络／缓存问题可重试三次；仍失败会尝试仅把本次新发布撤回草稿，不删除旧可用版。若 GitHub 故障导致撤回也失败，会明确报出撤回失败，需要检查本次发布状态，而不会宣称已撤回。

版本查询、补丁、测试、构建、签名或发布／OTA 检查失败时，通知任务自动在本仓库创建 Issue 并 @ 仓库账号 meiti789789。每次失败执行各有一条通知，同一执行重入不重复创建。Issue 包含失败步骤、可确定的直接保护错误、失败测试名称／异常类型和该次执行日志链接；不复制签名资料、原始日志或测试断言中的敏感值。主动取消构建不会当成故障通知。无法确定最终根因时会明确说明需要继续排查。

通知通过 GitHub 送达，不是本聊天自动推送。请在 [GitHub 通知设置](https://github.com/settings/notifications)开启参与／被提及事项的站内和邮件提醒，并在 Actions 通知中开启失败工作流提醒作为备用。账号通知是否启用、邮箱是否可投递和 GitHub 本身故障不受本仓库控制；不能把创建 Issue 等同于用户已读。说明见 [GitHub 官方通知文档](https://docs.github.com/en/subscriptions-and-notifications/get-started/configuring-notifications) 与 [Actions 通知设置](https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-github-actions-notifications)。

本轮没有通过人为制造真实故障来发送测试通知；消息内容、测试错误提取和新发布撤回行为使用自动测试验证。当前发布仅做公开只读 OTA 检查，不改应用版本或车机。
